# One Only devnet app

The early-access site is `https://oneonly.lol` (Vercel `kade/oneonly`, database `oneonly-db`). The app is `https://app.oneonly.lol` (Vercel `kade/oneonly-app`, database `oneonly-app-db`). Both use the workspace source, with isolated release directories generated by `scripts/prepare-release.mjs`. Do not deploy the entire workspace to the landing project directly.

## Available flows

Wallet Standard connection and signed-message login; image upload; normalized ticker availability and atomic registry claims; immutable token metadata; token creation plus a first buy in one transaction; slippage-protected buys and sells; partial final curve buys; reviewed DBC-to-DAMM v2 graduation; curve creator and graduated LP fee claims; SOL/USDC and configured quote balances; recoverable transaction status; discovery, curve progress, and indexed trade charts. There are no seeded market listings or fabricated balances. Smoke-test tokens are explicitly named as devnet tests.

The server uses Meteora’s `@meteora-ag/dynamic-bonding-curve-sdk@1.5.12` and `@meteora-ag/cp-amm-sdk@1.4.8`. It prepares a transaction, preserves its exact message in PostgreSQL, and accepts only that message with valid signatures from the intended wallet. Launch mint keypairs are ephemeral and discarded after partial signing. User wallet private keys never reach the server. Transaction signatures are persisted before broadcast, so an unknown RPC outcome is polled rather than treated as a failed purchase. A token is activated only after confirmed chain success and verification of pool creator, mint, and configuration.

The SDK is server-only. Wallet libraries load on app routes. The landing page remains static and uses the existing optimized art and sounds.

## Inactivity and history

An active ticker is unique within the One Only devnet registry. Names normalize to uppercase ASCII letters/digits after stripping a leading dollar sign and whitespace. Unicode is rejected before case folding. Ticker ownership is not a claim of global uniqueness across the permissionless Solana ecosystem.

The registry releases a ticker only when every active pool has less than $100 in volume on each of 30 complete UTC days, and activity today has not already reached $100. Every pool must have complete finalized-chain indexing coverage across that period. Unknown valuations, missing transactions, unrecognized swap events, or an unfinished backfill block release. The job deletes the claim, marks the historical listing released, and preserves its mint, pool, trades, and balances. A stale worker cannot delete a newer owner's claim. An abandoned draft's reservation is released only after its blockhash expires and its pool is absent, or a failed chain transaction is verified.

`deployment/app.vercel.json` invokes `/api/launchpad/cron` every five minutes, using Vercel's `CRON_SECRET` bearer header. The indexer reads pool address signatures, checkpoints history pages, decodes Anchor self-CPI events, deduplicates legacy/v2 swap events, and inserts idempotent signature/event rows. It uses historical Coinbase minute candle highs to conservatively value quote volume; a missing candle remains unknown rather than being valued at zero. Daily release uses UTC boundaries. Large backfills continue across invocations.

## Validation

`pnpm test` covers schema migrations in PGlite, concurrent ticker claims and reclaims, decimal precision, Unicode rejection, complete-day/coverage requirements, curve economics, and real devnet event decoding. The event regression fixture comes from a confirmed devnet swap that emitted both legacy and v2 events.

`pnpm test:e2e` covers desktop/mobile navigation, wallet signatures and replay rejection, origin checks, and the early-access flow. `node scripts/visual-check-app.mjs` captures the app at desktop/mobile widths.

`node scripts/smoke-devnet.mjs` performs a real SOL launch, buy, sell, creator fee claim, and holdings read through the app APIs, using the generated test-only wallet. Set `SMOKE_APP_URL=https://app.oneonly.lol` to test the deployed app. The last token ID and launch signature are recorded in `.data/devnet/last-smoke.json`; use `SMOKE_RESUME=true` to continue its buy/sell/claim checks without creating a second token. This command spends devnet test funds only.

## Current scope

Trading works on both the DBC curve and its derived official DAMM v2 destination. A final curve buy can consume less than its maximum input; the review shows the estimated spend. When the curve is full, anyone can review and pay for graduation. The app has no server hot wallet and does not silently pay migration rent. After graduation, live snapshots, trades, charts and LP fee claims use DAMM v2. Curve fees remain separately claimable.

Indexer cursors remain separate by venue. DBC coverage must reach the verified DAMM initialization boundary, and DAMM history must be complete, before graduated activity can release a ticker. Unknown historical USD prices keep tickers claimed. A missing market price stays unavailable rather than being fabricated.

The stock/token catalog supports configured mints without token extensions. Issuer-specific Token-2022 transfer hooks or transfer fees require their adapter before those assets can be enabled. The original brief (`bible.md`, Creating a Token) specifies Backed Finance xStocks: SPYx, QQQx, NVDAx, TSLAx, and CRCLx. Their issuer mint addresses, devnet availability, and extension compatibility still require verification; none are represented as available by default. General Jupiter swap routing, comments and P&L accounting are outside this release. X OAuth remains the independent early-access identity flow and still needs the project's OAuth 2.0 client credentials.

The workspace pins `rpc-websockets>uuid` to 11.1.0 because the websocket package loads UUID through CommonJS while UUID 12+ is ESM-only. Test server imports with `NODE_OPTIONS=--no-experimental-require-module` when updating this dependency.

## Discovery and TradingView charts

Discovery defaults to rolling 24-hour USD volume, with Market Cap and Newest alternatives. Search matches names, tickers, and mint/contract addresses. Rankings and filtering run in PostgreSQL before 24-item pagination, so older high-ranking tokens are not lost behind the newest launches. SOL and USDC market caps use the current USD reference; missing references remain unavailable. Indexed volume is marked as such when recent indexing coverage is incomplete. Missing historical valuations remain unknown. Graduated tokens stay visible with an explicit badge; DAMM market cap uses its live pool state and indexed volume includes both venues. Coverage remains explicitly incomplete until the graduated scan finishes.

The paired-with groups are All, SOL, Stocks, USDC, and Tokens. SOL and USDC are configured. The five stock assets and additional token quote assets still need their actual mint addresses and devnet DBC configurations; their categories show a clear unavailable state until entries are provided.

Token charts use [TradingView Lightweight Charts 5.2.1](https://tradingview.github.io/lightweight-charts/docs), loaded only on token-detail pages. Candlesticks and quote-volume bars are aggregated from indexed execution prices, with 1m, 5m, 15m, 1h, 4h, and 1d intervals. Times are UTC. Empty intervals do not fabricate candles. Each page covers at most 500 interval buckets ending at the latest indexed trade; Earlier history reads the preceding available window, and Latest trades returns to polling. OHLC values use database decimal aggregates and only become JavaScript numbers for chart rendering. Trades within the same timestamp use signature/venue/event-index order consistently, since the stored history does not include transaction positions within a block. The chart provides crosshairs, zoom/pan, fit, a volume legend, an accessible candle table, retry controls, and the required TradingView attribution. This is the Lightweight Charts library, not the licensed Advanced Charts terminal or Pine Script.


## Quote-asset catalog

`ONEONLY_QUOTE_ASSETS` is a server-only JSON array. SOL and devnet USDC are built in and cannot be overwritten. Each additional entry needs `network: "devnet"`, a unique uppercase `symbol`, `name`, `category` (`Stocks` or `Tokens`), the actual devnet `mint`, exact `decimals` (0–9), and its on-chain DBC `config`. Optional `referenceMint` identifies the corresponding **mainnet** asset solely for a USD reference; it never changes the transaction mint or network. No private keys belong in this configuration. The five intended stocks are SPYx, QQQx, NVDAx, TSLAx, and CRCLx; verify their issuer mint addresses and devnet counterparts before enabling them. The brief also names JUP, MET, BACKPACK, and Jito as additional token pairs; verify their exact token identities and mints rather than inferring them from project names.

For additional assets, configure `JUPITER_API_KEY` and preferably a dedicated `MAINNET_PRICE_RPC_URL`. The app checks the Jupiter price block time and rejects references older than two minutes. A missing or stale price closes new launches for that asset; it does not substitute a made-up value. Historical USD valuation for extra assets remains unknown, so their tickers cannot release automatically until a historical price adapter is supplied. SOL/USDC retain historical Coinbase references. See [Jupiter Price API](https://developers.jup.ag/docs/price).

New token records persist the quote mint, decimals and category. Subsequent catalog edits cannot silently change an existing token's unit conversion. USD ranking also checks the mint identity before applying a quote reference. The configuration verifier checks immutable six-decimal, one-billion supply, the published curve fees, permanent LP splits and the DAMM migration option.

## Release checks and mainnet handoff

Run `pnpm typecheck`, `pnpm test`, and `pnpm test:e2e`. `pnpm check:launch` is read-only and uses the caller's environment; it prints no credentials. Add `--mainnet` to make it fail until a mainnet release has actually been implemented and verified. To check a local env file, run `node --env-file=apps/web/.env.local --import ./packages/db/node_modules/tsx/dist/loader.mjs scripts/check-launch-readiness.ts`.

`pnpm test:graduation` spends only devnet SOL on an isolated 0.2-SOL-threshold config, then verifies the final partial buy, graduation, DAMM buy/sell, emitted events and LP fee claim. It never overwrites the deployed SOL configuration. `GRADUATION_RESUME=true` reuses that test pool. `pnpm test:indexer` reads its finalized history into an isolated in-memory PGlite database and verifies both venue boundaries and idempotency. Regression fixtures preserve the real devnet DAMM events.

Before mainnet: supply the fee receiver and approved economics; identify the five stock issuer mints and any additional quote tokens; verify issuer extension requirements; configure dedicated transaction/reference RPCs, production prices and mainnet DBC configs; use an isolated mainnet database; update the shared network/mint settings and wallet/explorer chain; verify the indexer schedule, migration flow and low-value end-to-end tests before opening launches. Devnet tokens, configs, test wallet keys and transaction records must not be reused as mainnet assets. Mainnet support is implemented; activation status and remaining work are tracked in [mainnet.md](mainnet.md).

The app title, metadata and share graphic use the One Only brand. The active network remains visible in the wallet area and transaction review. Each token now has its own canonical URL and sharing metadata. Early-access remains a separate surface.
